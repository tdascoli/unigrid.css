Required vs. Optional

Optional fields are labelled "(optional)" instead of marking required fields with asterisks. This frames most fields as expected, reducing the feeling of burden (behavioral economics: friction reduction).

No asterisk needed -- label implies required

Realistic Form Layout

Multiple inputs in a responsive grid. Related fields chunked into groups (3-5 per group). On mobile: single column. On tablet+: two columns for related field pairs.

Accessibility Notes

  • Label association: Every input has a <label> with matching for/id.
  • Error announcements: role="status" + aria-live="assertive" on error messages.
  • Invalid state: aria-invalid="true" set on error inputs.
  • Description link: aria-describedby connects to hint/error text.
  • Required: aria-required="true" for required fields.
  • Color independence: Error/success use icon + text, never color alone.
  • Focus ring: 2px border + 1px shadow = 3px visible indicator. Tab through the inputs above to test.
  • Touch target: Minimum 44px (sm) / 56px (md) / 64px (lg) height.
  • Contrast: All text meets 4.5:1 AA. All UI borders meet 3:1.
  • Reduced motion: All transitions disabled under prefers-reduced-motion: reduce.
  • High contrast: forced-colors: active uses system color keywords.
